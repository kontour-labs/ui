# Localisation

Everything that changes between readers in different places, and where the
library lets you change it: the locale, how numbers and dates are written, the
words, the script and its fonts, and the direction a page reads in.

The library ships English and nothing else. It does not bundle translations or
fonts; it makes every word reachable, every number and date the reader's own,
and every layout safe for scripts and directions that are not Latin and
left to right.

---

## The locale

`KontourTheme` takes a `locale`, and by default it is the device's, followed
while the app runs: Android reports a change through its configuration, iOS
through `NSCurrentLocaleDidChangeNotification`, a browser through
`languagechange`. A desktop JVM reads its locale once.

```kotlin
// The device's language, the usual case: nothing to pass.
KontourTheme { App() }

// An in-app language setting.
KontourTheme(locale = Locale("de-DE")) { App() }
```

A locale written in the other direction from the device's sets the layout
direction too, so `Locale("ar")` on an English phone lays out right to left. A
nested theme inherits the enclosing theme's locale, as it inherits contrast and
reduced motion.

## Numbers, dates and times

`Theme.formats` is a [`LocaleFormats`](components/locale-formats.md): integers
grouped the reader's way, decimals, percentages and money, month and weekday names,
dates in four lengths, times on the reader's clock, relative times, lists and
plurals. Every component that puts a number or a date on screen reads it —
pagination, badges, ratings, steppers, counters, calendars, time pickers — so a
German reader gets `1.234` and `14:05`, and a reader in Cairo Arabic-Indic
digits.

```kotlin
val formats = Theme.formats
Text(formats.date(departure, DateStyle.Medium))   // 5 Jun 2026 · 5. Juni 2026 · 2026/06/05
Text(formats.integer(riders))                      // 12,345 · 12.345 · ١٢٬٣٤٥
Text(formats.relativeTime(-5, RelativeUnit.Minute)) // 5 min ago · vor 5 Min.
```

The names and patterns are the platform's CLDR: ICU on Android, Foundation on
iOS, `Intl` in a browser, the JDK on a desktop. English is the library's own
table, with the region's conventions still read from the platform — so the
pictures in these docs and the goldens in its tests do not move between
machines. `LocaleFormats.english()` is that table on its own, and what a test
should pin itself to.

### Changing one thing

The three conventions people change most — the hour cycle, the order of a
date's parts, the first day of the week — change without touching the rest:

```kotlin
val formats = Theme.formats
ProvideTokens(formats = formats.withConventions(formats.conventions.copy(hourCycle = HourCycle.H23))) {
    Timetable()
}
```

A tag says the same in fewer words, and wins over the platform on every target:
`en-AU-u-hc-h23` is a 24-hour clock, `-u-fw-mon` a Monday week, `-u-nu-latn`
Western digits. On Android the reader's "Use 24-hour format" switch overrides
the locale's clock, and on iOS the 24-Hour Time switch does; both are followed
live. And `LocaleFormats` is an interface, so an app that needs one member
written its own way delegates to the one it has and overrides that member.

### Where a platform cannot say

The JDK has no relative-time formatter, so a desktop app in a language other
than English says "in 5 min" in English, and before JDK 22 it has no list
formatter, so lists are joined with commas. Android before 13 and iOS have no
"or" list and join those with commas too. Plural rules never depend on the
platform: they come from one CLDR table in the library, generated by
`docs/pull-cldr-plurals.py`, so an Arabic reader gets the same six forms on
every device.

## Words

Every word the library puts on screen is a field of
[`Strings`](theming.md#overriding), and a phrase with a number in it takes a
`Quantity` — the number already in the reader's digits, and the plural form it
takes in their language — so a translation can put the number anywhere and pick
the right word for it:

```kotlin
KontourTheme(
    strings = Strings(
        peopleCount = { n -> n.select(one = "${n.formatted} Person", other = "${n.formatted} Personen") },
        pageOfCount = { page, count -> "Seite ${page.formatted} von ${count.formatted}" },
    ),
) { App() }
```

### From your own resources

An app already has a way to translate its own words, and `Strings.from` reads
the library's through it. Each field is asked for by name, and each phrase with
a number asks for its plural form with the `Quantity` itself — the number, for a
resource system that chooses by number as Android's does, and its category, for
one that chooses by name — with `%1$s`, `%2$s` for its arguments:

```kotlin
// Android resources.
val strings = Strings.from(object : StringLookup {
    override fun text(key: String) =
        resources.getIdentifier("kontour_$key", "string", packageName).takeIf { it != 0 }?.let(resources::getString)

    override fun plural(key: String, quantity: Quantity) =
        resources.getIdentifier("kontour_$key", "plurals", packageName).takeIf { it != 0 }
            ?.let { resources.getQuantityString(it, quantity.value.toInt()) }
})
```

`python3 docs/export-strings.py` writes the English as an Android
`strings.xml`, `<plurals>` included, for a translator to start from. Compose
Multiplatform resources and moko-resources plug in the same way: a
`StringLookup` is two functions.

**`Strings()` is English whatever `locale` says.** The theme's `locale` changes
how numbers, dates and lists are written, and the layout direction, and not one
word: the words are the app's, built from the app's resources. So an in-app
language setting builds them again when it changes:

```kotlin
val strings = remember(locale) { Strings.from(lookupFor(locale)) }
KontourTheme(locale = locale, strings = strings) { App() }
```

A key the lookup has nothing for falls back to the English, so a translation
that is missing one says it in English rather than saying nothing. The charts
have words of their own, `ChartStrings`, built the same way with
`ChartStrings.from(lookup)` over the same lookup, and provided with
`LocalChartStrings`.

## Scripts and fonts

The bundled faces — Outfit and JetBrains Mono — are Latin. For any other script
the reader gets their platform's own font, the one they read everything else
in. What the library does, by default, is make its type scale safe for the
locale's script: every style is told its locale, so the platform chooses the
right glyphs and line breaks; tracking goes to zero for scripts that join their
letters or have no case; lines get taller and leading untrimmed for scripts whose
marks reach above and below a Latin line; and no italic is synthesised where
there is no italic tradition.

An app with its own face for a script gives it through `ScriptTypography`:

```kotlin
KontourTheme(
    scriptTypography = ScriptTypography(families = mapOf("Jpan" to notoSansJp, "Arab" to notoNaskh)),
) { App() }
```

On a Skia platform — iOS, desktop and web — this is the only way to choose
Japanese rather than Chinese forms of the same Han characters. On the web,
Compose downloads Noto from Google's font servers by itself for a script the
bundled faces do not cover, which a strict content security policy or an offline
app will refuse: supply the faces and preload them with
`rememberFontsPreloaded`.

Buttons and chips have a minimum height, not a height, so a label in a tall
script or at 200% type grows the control rather than being cut off.

## Right to left

Everything that follows the reading direction follows it: rows and bars start on
the right, the switch turns on towards the left, progress fills from the right,
a half star is lit on its right, drags and arrow keys go the way they point. The
colour picker's hue and opacity tracks mirror; its square does not, because it
is a picture of colour and not text. A knob keeps its clockwise turn. Numbers
inside right-to-left text read left to right, and counts like `+3` and `99+` are
isolated so their plus stays where it was written.

On Android, set `android:supportsRtl="true"` in the manifest. On iOS, list the
app's languages in `CFBundleLocalizations` so the system offers them.

## Testing without a translation

`PseudoLocalised` runs a screen in a language that does not exist:

- **`Accented`** — every letter accented, every string bracketed and 40%
  longer. A word still in plain English was never routed through `Strings`; a
  bracket cut off is a label that truncates.
- **`Bidi`** — every string reversed, the layout right to left, the digits
  Arabic-Indic. What still reads left to right was laid out by hand.
- **`Tall`** — marks stacked above and below every letter. A clipped mark is a
  line height or a fixed box too small for half the world's scripts.

```kotlin
PseudoLocalised(PseudoLocale.Accented) { App() }
```

The catalog's settings have all three, beside right to left. The library's own
tests run every component under them.
